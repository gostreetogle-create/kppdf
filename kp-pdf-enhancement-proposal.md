## 🔍 Анализ текущего состояния

### Текущая архитектура
Система генерации PDF использует **Puppeteer** для открытия Angular-страницы КП с параметром `?pdf=1`. Генерация происходит через компонент `KpDocumentComponent`, который рендерит:
- Таблицу с товарами
- Фоновые изображения (первая и последующие страницы)
- Текстовые блоки: headerNote, introText, footerText, closingText

### Текущие возможности
- ✅ Генерация PDF через Puppeteer
- ✅ Кэширование PDF
- ✅ Поддержка версий КП
- ✅ Настройка фоновых изображений через `companySnapshot.assets`
- ✅ Стандартная структура таблицы (8 колонок)

### Текущие ограничения
- ❌ **Отсутствие текстовых полей в шаблонах** - тексты жестко закодированы или берутся из `companySnapshot.texts`, которое не заполняется из шаблонов
- ❌ **Нет возможности кастомизации текстов** для разных компаний
- ❌ **Одинаковые тексты для всех КП** независимо от отправителя

## 🚨 Проблемы и ограничения

### 1. **Текстовые блоки не настраиваются**
Сейчас все компании используют одинаковые тексты в PDF, что не позволяет дифференцировать КП от разных отправителей.

### 2. **Нет связи шаблонов с текстами**
В модели `Counterparty` есть `brandingTemplates` с `assets`, но нет текстовых полей. Это делает шаблоны неполноценными для полной кастомизации дизайна.

### 3. **Сложность поддержки**
При изменении бизнес-логики нужно править несколько мест: модель, API, фронтенд, валидацию.

## 📁 Бизнес-логика по категориям

### 1. Текстовые блоки

| Поле | Назначение | Источник | Fallback |
|------|------------|----------|----------|
| `headerNote` | Примечание в шапке (например "Ответ на запрос №...") | Только из шаблона | Пустая строка |
| `introText` | Вступительный текст | Только из шаблона | Пустая строка |
| `footerText` | Текст в футере (контакты, условия) | Шаблон → Компания | Пустая строка |
| `closingText` | Заключительный текст (подпись) | Только из шаблона | Пустая строка |

### 2. Шаблоны

**Типы КП** (KpType):
- `standard` - Стандартное КП
- `response` - Ответ на письмо/запрос
- `special` - Специальное предложение
- `tender` - Тендер
- `service` - Услуга

**Активы шаблона**:
- `kpPage1` - Фон первой страницы (обязательный)
- `kpPage2` - Фон второй страницы (опциональный)
- `passport` - Фон для паспорта товара
- `appendix` - Фон для приложения

**Условия** (conditions) - массив строк с условиями.

---

### 3. Компании

**Поля компании**:
- `footerText` - Глобальный футер компании (fallback для шаблонов)
- `brandingTemplates` - Массив шаблонов
- `isOurCompany` - Является ли нашей компанией
- `isDefaultInitiator` - Компания по умолчанию для новых КП

**Логика выбора шаблона**:
1. Если `templateKey` указан - выбираем шаблон с этим ключом и типом КП
2. Если `templateKey` = 'auto' - выбираем шаблон по умолчанию для типа КП
3. Если шаблон не найден - используем первый шаблон для типа КП

## 💬 Пожелания пользователя

Из вашего описания я выделил следующие ключевые требования:

### 1. **Разные КП для разных компаний**
> "нужно чтобы при выборе поставщика (компании) КП менялся фоновый рисунок и расположение текстов"

**Реализация**: 
- Каждая компания имеет свои шаблоны с уникальными `assets` и `texts`
- При выборе компании система подтягивает соответствующий шаблон
- Поддержка разных типов КП (response, standard и т.д.)
